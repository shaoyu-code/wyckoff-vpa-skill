## 四、代码位置与可重现方式

GitHub的本目录`parts/`保存相对已发布r1的全部r2+r3源码差异；分片仅为传输，必须按SOURCE_DELTA.json顺序合并。每片字节数、SHA-256和Git blob，以及完整输入/输出源码指纹都有登记。`build_r3.py`先调用哈希锁定的既有r1重建器，再应用全部差异，只在临时目录操作，最后输出一个新的候选ZIP；不安装、不访问TV、不运行应用代码、不联网。

```bash
python3 delivery/wyckoff-tv-v1.1/r3/build_r3.py --baseline-zip <已有9月19日历史源码ZIP> --out <新的候选源码ZIP>
python3 -m unittest discover -s delivery/wyckoff-tv-v1.1/r3 -p 'test_build_r3.py' -v
```

历史ZIP必须为SHA-256 `60cf79cb04f58a3cbc58f17c08a9c229a9d24837aa20b66ae61b83d92f935ad4`；不同基线立即拒绝。它不是用户当前运行目录，不能用未知本机目录代替。源码指纹是全部相对路径与文件SHA-256的规范化映射，不依赖ZIP时间戳。本地交付包另附完整713文件候选ZIP、从原历史基线开始的累计44文件修复、只读预检与原始测试日志，不需要人工编代码。
