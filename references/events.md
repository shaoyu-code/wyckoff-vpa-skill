# 事件候选、确认与开单纪律

脚本输出的是 candidate。事件确认必须同时满足位置、量、后续反应和完整身份匹配；确认文本不能替代候选证据。

| 代码 | 规则证据 | 确认重点 | 常见误报 |
|---|---|---|---|
| SC | 下跌背景、宽幅高量、低位收盘特征 | 之后 1–5 根是否出现自动反弹 | 趋势中继大阴 |
| BC | 上涨背景、宽幅高量、高位收盘特征 | 之后是否失去续涨能力 | 趋势中继大阳 |
| SPRING | 刺破已识别箱体下沿后收回 | 后续回测缩量且不得再破 Spring 极值 | 真破位或普通 20 根低点 |
| UT | 刺破已识别箱体上沿后收回 | 后续反抽缩量且不得再破 UT 极值 | 真突破或普通 20 根高点 |
| SOS | 带量收在箱体上沿外 | 后续 LPS 守住边界 | 无量假突破 |
| SOW | 带量收在箱体下沿外 | 后续 LPSY 反抽失败 | 无量假跌破 |
| TEST_AFTER_SPRING / LPS | 核心事件后的低量回测 | 发生日期晚于核心事件、关联 ID 正确 | Spring 当根或跌破核心极值 |
| TEST_AFTER_UT / LPSY | 核心事件后的低量反抽 | 发生日期晚于核心事件、关联 ID 正确 | UT 当根或突破核心极值 |
| EFFORT_NO_RESULT | 相对量高但振幅/位移不匹配 | 只作为方向解释，不可单独开仓 | 把单根残差当买卖点 |

## 硬规则

- 多头：只允许 Spring 后的有效低量测试，或 SOS 后 LPS。
- 空头：只允许 UT 后的有效低量反抽，或 SOW 后 LPSY。
- Spring、UT、SC、BC 当根不入场。
- 回测若穿越定义核心事件的极值，不生成有效事件对。
- 所选事件对必须是最新且仍在时效窗口内的完整对；后面出现新的未解决核心事件时，旧对失效。
- `events_confirmed` 和 `events_rejected` 必须覆盖活动审查集合，防止只保留有利候选。
- 校验器按 `id + evidence_hash + 日期 + 类型 + 索引 + 价格 + 极值 + 边界 + 关联 ID` 逐项核对。
